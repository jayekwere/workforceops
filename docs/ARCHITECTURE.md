# Lifecycle architecture and recovery

The employee catalog is local, tenant scoped and seeded from trusted configuration. Identities, emails and provider endpoints are not selected by arbitrary request payloads. The request schema permits only catalog employee ID, one of three lifecycle actions and a known role template. Employees belong to one server tenant. Provider aliases and normalized endpoint authorities must be unique. Each SCIM client carries a separate server credential and a fingerprint of its configured scope and endpoint; caller access tokens never become upstream credentials.

A plan binds the local employee snapshot, desired account projection, provider identities, raw before-state including ETag, policy hash, requester, tenant and expiry. Review must come from another subject. Execution requires an operator distinct from both. A durable employee lock prevents competing workflows from changing the same employee while a partial or uncertain operation exists.

Each step has pending, dispatching, verified, blocked or uncertain status. Execution persists dispatch intent before network writes. A matching observed state is verified without a write. Otherwise it sends a conditional PATCH or creates a missing user, then independently fetches and checks the managed identity and projection. A failure before dispatch is known blocked. A transport error, lost acknowledgement or failed readback after dispatch is uncertain even when a write might not have occurred.

The execution key binds actor, plan and digest. A repeated key never repeats completed steps. Concurrent requests see a stored executing status. An execution lease changes on a claimed retry or reconciliation. Stale workers cannot persist old outcomes, and the lease is checked before dispatch. A thirty-second inactivity cooldown precedes reconciliation, measured from last saved activity rather than plan creation. Reconciliation fences the previous lease and only reads. It can verify a desired remote state, recover a claim that crashed before dispatch, or preserve uncertainty. It does not prove that an unacknowledged remote operation was the cause of a matching state, and cannot cancel an in-flight provider operation.

A known blocked workflow can be cancelled by an independent operator; a dirty uncertain workflow cannot be cancelled through that route. After all managed account steps are verified, catalog changes, lock release and completion evidence are committed together. Offboarding manual tasks remain separate. Recording their completion is an explicit operator attestation with note fingerprint and actor. It does not verify a physical action. The local demo and browser switch synthetic subjects controlled by one person.

The SCIM service in the lab is a bounded subset, not a certified full SCIM implementation. It supports a declared externalId filter, list, create, replace of active/displayName/roles, and ETags. The reference uses a private loopback listener and synthetic state. No arbitrary filter evaluator, bulk operations, password management, session clearing or group write-through exists. Its fault switch can return an unavailable read or lose an acknowledgement after an actual committed write.

Persistence and audit requirements are in OPERATIONS.md. There are no distributed leases, provider-side cancellation, transaction spanning multiple services, generic rollback, background HR feed or automatic license/data transfer. An operator must investigate unresolved uncertainty before attempting a separately approved operation.
